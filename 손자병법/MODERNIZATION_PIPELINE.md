# 손자병법 구절 페이지 전면 최신화 파이프라인

이 문서는 거의 매일 바뀌는 편집 기준을 기존 페이지 전체에 다시 적용하기 위한 전용 검수 절차다. 과거에 “완료”한 페이지도 현재 기준을 통과하지 못하면 자동으로 미완료 상태로 되돌린다.

## 실행

단일 페이지:

```bash
python3 손자병법/validate_full_modernization.py 손자병법/jiudi1_full_page.md
```

로컬 전체 페이지:

```bash
python3 손자병법/validate_full_modernization.py --all
```

## 강제 검사

- 1~5번 섹션과 자동 목차
- 11구절 기준의 원문·독음 통합 토글과 서사형 한자 풀이
- 서양·동양의 패군·승군 도천지장법 표 4개
- 도천지장법 표의 2열 구조, 행 순서, 이모지, 굵기, 첫 셀 배경색
- 패군·승군 결과 라벨
- 전투별 고품질 이미지 5종, 페이지당 총 10개 GitHub 영구 URL
- 만료되는 Notion 임시 이미지 URL 부재
- 전투마다 `法을 압축하지 않고 보기 — 곡제·관도·주용`
- 곡제·관도·주용 각각의 2열 비교표
- 각 비교표 안의 승군 파란색 진영 행과 패군 붉은색 진영 행
- 서양·동양 전투마다 승패를 가른 계책·오판·분기점을 제목에 담은 전투 서사

## 法 상세 비교의 고정 구조

각 전투의 승군 도천지장법 표 다음에 아래 묶음을 둔다.

1. `##### 法을 압축하지 않고 보기 — 곡제·관도·주용`
2. `곡제 曲制(곡제): 부대를 어떻게 나누고 결합했는가`
3. `관도 官道(관도): 누가 명령하고 어떻게 전달했는가`
4. `주용 主用(주용): 군량·장비·전투 지속 능력을 어떻게 썼는가`

세 항목은 각각 별도의 2열 표로 만든다. 첫 열에는 승군과 패군 진영을 놓고, 둘째 열에는 해당 항목의 실제 운용을 서술한다. 승군과 패군을 별도 문단이나 별도 표로 갈라놓지 않는다. 같은 표 안에서 바로 비교되어야 한다.

- 곡제: 병력 규모만 적지 말고 부대 분할, 병종 구성, 임무 결합을 비교한다.
- 관도: 지휘관의 직책·권한·상하관계, 명령·보고·군량 전달 경로를 비교한다.
- 주용: 군량, 식수, 장비, 숙영, 현지조달, 수송과 전투 지속 능력을 비교한다.

## 전투 서사의 고정 구조

각 전투의 초심자용 인물·지형 안내 바로 뒤에는 다음 형식의 서사 제목을 하나 둔다.

`#### 전투의 서사 — 배수진보다 먼저 있었던 ‘거절된 계책’`

또는 전역 규모가 큰 사례라면:

`#### 상세 전역 서사 — 적이 가장 느릴 것이라 믿은 길에서 가장 빠른 결론이 나왔다`

대시 뒤의 문구는 장식적인 소제목이 아니다. 독자가 본문을 읽기 전에 **무슨 계책, 정보, 오판, 지휘 충돌 또는 지형 선택이 승패를 갈랐는지** 먼저 잡게 하는 인과관계 안내문이다.

- `전투의 흐름`, `승리의 비결`, `치열했던 전투`처럼 어느 전쟁에도 붙일 수 있는 제목은 금지한다.
- 지나치게 소설적이거나 유치한 수사도 피한다.
- 잘 알려진 결과보다 그보다 앞선 원인과 분기점을 제목에 올린다.
- 제목 아래 본문은 전투 결과를 요약하지 말고, 제목이 제시한 원인이 어떻게 다음 장면을 불러왔는지 시간 순서로 이어 쓴다.
- 서양·동양 사례 각각 하나씩, 표준 페이지에는 정확히 두 개가 있어야 한다.

패군·승군 개별 분석에 앞서는 장편 전역 서사는 `셔먼의 바다로의 진군`을 기준으로 한다. 초심자용 인물·전역 소개와 핵심 지형 예고 뒤에는, 전초의 선택·거부된 계책·기만·우회·분산·보급·국지전·결정타·철수와 후일담을 판세가 바뀌는 장면마다 나누어 쓴다. 소제목은 해당 장면의 실제 인물·장소·명령·오판을 담아 자유롭게 짓고 네 개의 공통 제목으로 고정하지 않는다.

장편 서사 다음에는 `#### 法 한눈 비교 — 곡제·관도·주용` 4열 표 하나를 둔다. `진영 | 곡제(편제) | 관도(지휘) | 주용(보급·지속)`으로 승군·패군을 간단히 비교한다. 이 표는 초심자용 요약이며, 뒤의 곡제·관도·주용 상세 비교표 3개는 그대로 유지한다.

## 1번 섹션의 고정 구조

모든 구절의 1번 섹션은 九地篇 11구절 `凡爲客之道, 深入則專, 主人不克. 掠於饒野, 三軍足食.`의 1번 섹션을 기준본으로 삼는다.

1. 제목은 `## 1. 원문 + 독음 + 직역 + 한자어 뜻풀이`로 통일한다.
2. `<details color="orange_bg">`로 주황 배경 토글을 만든다.
3. 토글 제목 한 줄 안에 `원문<br>독음`을 넣는다.
4. 원문 전체를 칠하지 않고 구절의 논리를 끌고 가는 핵심 한자만 `<span color="red">...</span>`로 표시한다.
5. 첫 블록은 `**직역**`이다. 의역이나 교훈을 섞지 않는다.
6. 직역 다음 문단에서 구절 전체가 어떤 긴장과 인과관계를 가진 장면인지 먼저 설명한다.
7. 핵심 글자 또는 결합어마다 `#### 漢字(훈음) — 장면을 보여주는 소제목`을 둔다.
8. 각 풀이에는 자형·기본 뜻, 이 구절 안의 역할, 앞뒤 글자와의 관계, 역사나 생활에서 연상할 수 있는 구체적 장면을 연결한다.
9. 사전식 한 줄 풀이를 병렬로 나열하지 않는다.
10. 마지막은 반드시 `#### 글자들이 완성하는 한 장면`으로 닫고, 핵심 글자들이 순서대로 어떻게 하나의 논리를 완성하는지 다시 묶는다.

핵심 한자 수는 구절 길이에 따라 달라질 수 있으나 최소 세 묶음 이상을 원칙으로 한다. 조사·접속 기능만 하는 글자까지 억지로 늘리지 말고, 의미상 한 덩어리인 `主人`, `饒·足`처럼 묶는 편이 더 자연스러우면 함께 풀이한다.

마크업 조건을 채우는 것만으로는 부족하다. `凡爲客之道…` 기준본과 나란히 놓고, 직역 뒤 첫 문단이 구절의 긴장과 인과를 잡는지, 각 소제목만 읽어도 장면이 떠오르는지, 풀이가 자형에서 문맥과 실제 장면으로 이동하는지, 마지막 문단이 글자들을 원문 순서의 한 장면으로 묶는지 사람이 확인한다. 불릿형 사전 풀이와 `원문/독음/직역` 분리형 구식 블록이 하나라도 남으면 1번 섹션 전체를 다시 쓴다.

## 이미지 5종의 기준본과 품질 게이트

절대 기준은 `凡爲客之道…` 페이지의 셔먼·손책 시각 세트다. 생성형 단일 도구 사용 여부가 아니라 아래 독서 경험을 재현했는지로 판정한다.

- 주요 인물 안내판: 양 진영 여러 인물, 시대 복식, 총사령관의 시각적 위계, 파랑/빨강 진영 구분, 대결 구도.
- 조직도·편제: 실제 이름·직책·예하 부대·별도 임무, 실선과 점선의 의미, 아이폰에서도 보이는 상하관계.
- 시대 세력도: 당시 세력권과 주변 세력, 출발·전환·목표 거점, 서사의 강·산·도시. 군웅의 영향권은 외곽이 자연스럽게 번져야 한다.
- 전략지형도: 승패를 만든 지형이 먼저 읽히고 진격·유인·우회·차단·퇴로가 구분되어야 한다.
- 단계별 흐름도: 3~5패널 안에서 `명령/진언 → 기만/오판 → 전환 → 결과`가 시간순으로 이어져야 한다.

인물과 역사 분위기는 생성형 이미지로 만들고 정확한 이름·편제·지명·범례는 코드나 그래픽 편집으로 정리할 수 있다. 여러 전투를 한 접촉시트로 생성해 같은 틀로 잘라 쓰거나 이름만 바꾼 조직도·흐름도를 반복 생산하는 것은 금지한다. 전투마다 다섯 장을 개별 설계하고, 완성 뒤 기준본 열 장과 실제로 나란히 열어 비교한다.

## 사람의 최종 검수

자동 검사가 `PASS`여도 아래 세 항목은 사람이 확인한다.

- 장수와 참모의 모든 별칭에 승군 파란색·패군 붉은색이 적용됐는가
- 전투와 직접 관련 없는 지형까지 종류별 이모지와 배경색이 적용됐는가
- 이미지 10장을 실제로 열었을 때 순서·크기·가독성이 적절한가
- 이미지 10장이 셔먼·손책 기준본과 비교해 인물성·정보 위계·전역 이해도에서 뒤처지지 않는가
- 전투 서사 제목과 본문이 실제 계책·오판·분기점을 인과관계로 설명하는가

로컬 검사, 사람 검수, GitHub 배포, Notion 저장 후 재조회 검사를 모두 통과한 뒤에만 “전면 최신화 완료”라고 기록한다.
