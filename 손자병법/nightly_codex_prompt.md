# Codex 야간 손자병법 해석 작업

매일 한 번만 다음 미완료 손자병법 구절을 전면 최신화한다.

1. 작업 시작 즉시 `손자병법/README.md`를 처음부터 끝까지 다시 읽고, CLI 최종 메시지에 적용할 최신 규칙을 짧게 브리핑한다.
2. Notion 손자병법 원문과 완료 기록을 다시 조회하여 다음 미완료 구절을 하나만 고른다. 이미 완료된 구절을 중복 작업하지 않는다.
3. 사용자 승인 절대 기준본인 九地篇 12구절 `謹養而勿勞…` 페이지와 README의 정본 규칙에 따라 1~5섹션, 전통 주석가 전원, 교차 설명, 서양·동양 전역 서사, 양군 비교, 패배 회피 분기점, 실생활 적용을 축약 없이 작성한다.
4. 전투별 `주요 인물·병사/무기/생활·지휘 편제·시대 세력도·전략지형도·단계별 흐름도` 6종씩 총 12개를 제작한다. 각 종류마다 사용자 승인 기준본인 구지편 12구절의 카우펜스·채주 도판 2장(병사 안내판은 구지편 17구절 2장)과 이번 서양·동양 도판 2장을 같은 화면에서 나란히 열고, 원본 크기와 390px 축소본을 모두 비교한다. 실제 지형·수계·도로·세력 면·전투 고유 기동이 없는 평면 카드, 큰 원·다각형, 빈 베이지 배경, 점과 선, 글상자와 화살표만으로 채운 그림은 즉시 폐기한다.
5. 재현 원고와 최종 이미지만 Git에 선별 추가한다. 사용자 파일이나 관련 없는 변경은 절대 포함하지 않는다.
6. 본문 검증과 함께 `python3 손자병법/validate_visual_quality.py 손자병법/jiudi<번호>_full_page.md`를 실행한다. 이미지 종류별 2장·총 12장 구조와 기준본 대비 엔트로피·경계 밀도 하한을 통과해야 한다. 자동 통과 뒤에도 앞 단계의 실제 나란히 보기에서 지형 정보·전투 고유성·모바일 가독성 중 하나라도 기준본보다 현저히 낮으면 실패다. 모든 로컬 검증을 통과한 뒤 `git fetch origin`으로 원격 변경을 확인한다. 충돌이 있으면 임의 해결하거나 강제 푸시하지 말고 실패 사유를 기록하고 종료한다.
7. GitHub `main`에 정상 푸시하여 raw 이미지 URL이 접근 가능한지 확인한 뒤 Notion 분석 페이지를 만들거나 갱신하고 정확한 원문 토글 아래에 배치한다.
8. Notion을 다시 조회하여 원문 전체 독음 부제, 자동 목차 0개, 1~5섹션 각 1개, 2~5번 대형 토글, 이미지 10~12개, 임시 URL 0개, 원문 토글 내부 배치를 확인한다.
9. 검증 완료 후 README 완료 기록을 갱신해 다시 커밋·푸시한다. `git sparse-checkout reapply`로 로컬 최종 이미지 사본을 정리한다.
10. `손자병법/site`에서 `npm run sync:analysis`를 실행한다. 구절 원고와 README의 Notion 완료 기록을 자동 탐색한 생성 데이터가 새 구절을 포함하고, `/archive`의 구절 수와 `/verses/<새 번호>` 상세 페이지가 빌드 결과에 존재하는지 확인한다.
11. Sites 프로젝트 `appgprj_6a835b4cb6cc8191951e1cd18c4f0776`에 새 빌드를 배포하고 `https://sunzi-strategy-notes.pulpilisory.chatgpt.site/archive`와 새 상세 페이지를 다시 열어 원문·독음·역사 사례·Notion 정본 링크가 표시되는지 확인한다. 사이트 배포와 실페이지 재확인까지 성공해야 구절 분석 완료로 판정한다.
12. 사이트 실페이지 확인 뒤 `python3 손자병법/notify_tulpachat.py 손자병법/jiudi<새 번호>_full_page.md --notion-url <정본 URL> --site-url https://sunzi-strategy-notes.pulpilisory.chatgpt.site/verses/<새 번호>`를 실행한다. `병법가` 방에서는 소유자 계정이 아니라 전통 주석가 9명 중 구절별로 선택된 한 명이 새 분석의 원문·핵심 해석·클릭 가능한 두 링크와 토론 방향을 소개해야 한다. 찬반이나 동의 여부를 묻지 않으며, 각 병법가는 `핵심 판단에 동의합니다` 같은 판정형 문구 없이 자기 주석 관점의 쟁점 하나를 바로 논해야 한다. 소개자를 제외한 손무와 나머지 주석가의 토론 차례가 생성됐는지 응답의 `announcer`와 `notified`로 확인한다. 같은 구절의 중복 실행은 새 메시지와 토론을 만들지 않되, 공지 형식이 바뀌면 기존 메시지 본문은 최신 형식으로 갱신되어야 한다.
13. 완료 또는 실패 여부, 처리한 구절, Notion URL, Git 커밋, 사이트 URL과 배포 확인 결과, 병법가 방 보고 및 토론 시작 결과를 최종 메시지에 명확히 적는다. 중간 승인을 기다리며 멈추지 말고 안전한 범위에서 대안을 찾되, 인증 만료·충돌·사료 불확실성·사이트 배포 또는 병법가 보고 실패처럼 결과를 훼손하는 문제는 실패로 보고한다.

절대 `git push --force`, `git reset --hard`, 광범위 삭제, 관련 없는 파일 커밋을 하지 않는다. 한 번 실행할 때 구절 하나만 처리한다.
