# 경진대회시스템

경진대회를 일회성 이벤트가 아니라 **실전 학습·완주 경험·포트폴리오 증거를 만드는 반복 시스템**으로 운영한다. 이직시스템에서 발견한 부족 기술을 대회에서 사용하고, 결과물과 회고를 다시 이력서·GitHub·면접 자료로 돌려보낸다.

## 전체 흐름

`D대회 발견 → 출전 판단 → 기초선 완성 → 개선 실험 → 제출 → 결과·회고 → 포트폴리오 전환`

순위가 낮더라도 마감 안에 제출하고, 재현 가능한 코드와 판단 기록을 남기면 성공적인 출전이다. 수상만 목표로 잡으면 난이도가 높은 대회를 피하게 되므로, 참가 초기에는 **완주율과 학습 전환률**을 더 중요하게 본다.

## 대회 유형

- **데이터·AI 경진대회:** 지표 개선, 검증 설계, 피처 엔지니어링, 실험 관리를 연습한다. Kaggle·DACON 등을 조사한다.
- **해커톤·제품 개발:** 문제 정의, MVP, 사용자 가치, 데모·발표를 훈련한다. Devpost·국내 공공기관 해커톤 등을 조사한다.
- **알고리즘·코딩 대회:** 문제 해결 속도와 자료구조·알고리즘 기초를 점검한다.
- **아이디어·공모전:** 시장·문제·실행 계획을 설득력 있게 구조화한다.

## 출전 판단 기준

대회를 발견하면 다음을 먼저 적는다.

- 주최자와 플랫폼은 신뢰할 수 있는가?
- 거주지·나이·학생·재직 등 참가 자격에 맞는가?
- 실제 마감일과 제출물은 무엇인가?
- 데이터·코드·생성물의 라이선스와 저작권 조항은 어떤가?
- 사용 가능한 시간에 적은 기능으로라도 완주할 수 있는가?
- 이직 목표의 요구 기술과 연결되는가?
- 결과가 나쁘더라도 코드·기술 문서·데모로 남길 수 있는가?

### 우선순위 점수

`(직무 연관성 × 30) + (포트폴리오 가치 × 25) + (학습 가치 × 20) + (완주 가능성 × 25)`으로 평가한다. 각 항목은 0~5점으로 입력하고 100점으로 환산한다. 상금은 보조 정보일 뿐 핵심 점수에는 넣지 않는다.

## 실행 루틴

### 매주 20분 — 대회 정찰

1. Kaggle, DACON, 정부·공공기관 공모전, Devpost를 확인한다.
2. 마감이 남은 대회만 기록한다.
3. 우선순위 점수가 높은 3개를 다시 검토한다.
4. 동시 진행은 최대 1개로 제한한다.

### 참가 중 — 빠른 완주

1. 첫 20%의 기간 안에 규칙·평가지표를 읽고 최소 제출을 완성한다.
2. 기초선을 고정한 뒤 실험은 한 번에 한 변수만 바꿄고 기록한다.
3. 제출 24시간 전에 코드·문서·발표 자료를 고정한다.
4. 제출 후 48시간 안에 회고를 남긴다.

## 포트폴리오로 전환할 자료

- 문제 정의와 평가지표를 내 말로 설명한 문서
- 첫 기초선에서 최종 결과까지의 실험 기록
- 잘된 실험뿐 아니라 실패한 가설과 수정 이유
- 재현 가능한 실행 방법·의존성·환경
- 순위보다 문제 해결 판단이 드러나는 README
- 2~3분으로 설명할 수 있는 데모·발표자료
