# 박동근 경력·포트폴리오 근거 요약

이 문서는 다른 Codex·Claude 세션과 `job_collector.py`가 후보자의 실제 근거를 빠르게 파악하기 위한 사람용 요약이다. 구조화된 원본은 `candidate_profile.json`이며, 연락처·주소·생년월일·주민번호·계좌·건강정보는 저장하지 않는다.

## 한 문장 정체성

**반도체·센서 연구 경험을 실제 AI·데이터·업무 자동화 서비스로 연결하는 개발자.**

대학·대학원에서 전자정보공학과 반도체·바이오센서 측정 자동화 및 데이터 분석을 경험했고, 이후 Python·SQL·백엔드·모바일 앱 교육과 팀 프로젝트를 거쳐 개인 업무 자동화 파이프라인을 직접 운영하고 있다.

## 목표 직무

- 데이터·AI 엔지니어
- Python 백엔드 개발자
- 제조·반도체 데이터 분석 및 자동화

## 대표 포트폴리오 우선순위

### 1. 일본어 영상 학습 자동화 파이프라인

Whisper 자막, 번역·후리가나, 장면 이미지, AI 학습카드, FFmpeg 미디어 처리, TTS 낭독판 EPUB을 하나의 운영 파이프라인으로 연결했다. 캐시, 재시도, 중간 저장과 중단 복구를 적용했다. AI·업무 자동화, Python 백엔드, 장기 작업 운영 공고에 가장 먼저 제시한다.

### 2. Shift Alarm 교대근무·개인 업무 자동화 도구

macOS 메뉴바와 launchd를 중심으로 근무 일정·알람·Notion 체크리스트·iPhone 위젯·전자책·자막 작업·AI 사용량을 통합했다. 매일 실제 사용하는 도구이며 설정 보존, 상태 JSON, 오류 로그, 자동 재시작을 갖췄다. 사내 업무 자동화와 운영 도구 공고에 제시한다.

### 3. 채용공고·기업·경진대회 분석 이직시스템

사람인·고용24 API, 허용된 공개 소스, SQLite, DART, LLM, Notion을 연결해 공고 수집→기술 분석→프로젝트·지원서 과제화를 자동화했다. 데이터 수집, API, 백엔드, AI 에이전트형 업무 자동화 공고에 제시한다.

### 4. 하루시작 — 지하철 혼잡도 예측·뉴스 감정분류 앱

3인 팀의 팀장·데이터 분석·백엔드를 맡았다. 서울 지하철 8개 노선의 2018~2024년 데이터와 배차 정보를 합쳐 약 396만 행·51열, 약 1GB의 데이터를 정제했다. KNN·XGBoost·Random Forest·선형회귀를 비교하고 AWS Ubuntu의 Flask·FastAPI에서 SwiftUI 앱으로 JSON 결과를 제공했다. 데이터·ML 엔지니어 공고에 제시한다.

### 5. 반도체·바이오센서 측정 자동화 및 예측 연구

LabVIEW·Arduino·Python으로 측정 시스템을 자동화하고 실험 데이터를 정제해 반도체 문턱전압과 센서 특성 예측에 머신러닝을 적용했다. 제조·반도체·실험 자동화 공고에서 도메인 차별점으로 사용한다.

### 보조 프로젝트

- **Reco-Farm:** 기상·토양·생산량 데이터, Random Forest·SVM·ARIMA, Flutter·Spring Boot·AWS를 이용한 농산물 생산량·가격 예측
- **Apple King:** Java·Spring Boot·MySQL 기반 전자상거래 CRUD, 검색·정렬·페이징·구매·관리자 기능
- **행복좌석:** 액티브 시니어 좌석예매 키오스크, ERD 반복 설계, XOR 좌석 상태 알고리즘, DB 주기 동기화, PR·코드 리뷰 관리

## 자소서 핵심 서사

### 지원 동기 — 연구에서 소프트웨어로

반도체 연구 중 측정 자동화와 데이터 기반 예측 문제를 코딩으로 해결할 때 가장 큰 흥미를 느꼈다. 이를 계기로 AI·데이터·웹·앱 개발을 학습하고, 연구 데이터를 서비스와 운영 자동화로 연결하는 방향으로 전환했다.

### 직무 경험 — 대용량 데이터 모듈화

연도·노선마다 구조가 다른 지하철 데이터를 표준화하고 배차·날짜 특성을 병합하는 전처리 및 모델 입력 변환을 모듈화했다. 약 1GB 데이터로 여러 모델을 비교했고 팀원들이 같은 코드를 재사용할 수 있게 했다.

### 리더십 — 숙련도가 다른 팀 운영

여러 교육 프로젝트에서 팀장을 맡아 역할을 현실적으로 재조정하고 페어 프로그래밍, 질문 중심 코칭, 코드 리뷰를 적용했다. 빠듯한 일정에서 목표만 밀어붙이는 단점을 인식한 뒤 팀원의 상황과 의견을 더 일찍 확인하는 방식으로 보완했다.

### 입사 후 기여 — 데모가 아닌 운영

최근 개인 프로젝트에서는 기능 구현 뒤에도 로그, 캐시, 재시도, 상태 파일, 자동 재시작, Git·Notion 동기화를 계속 보강했다. 입사 후에도 반복 업무를 찾고 작은 자동화부터 실제 운영 가능한 도구로 확장하는 방식으로 기여한다.

## 맞춤 작성 규칙

1. 공고 요구사항과 직접 연결되는 프로젝트만 2~3개 선택한다.
2. 문제→판단·행동→결과 순서로 쓰고, 검증된 숫자만 사용한다.
3. 연구 경험은 제조·반도체 공고에서, 최근 운영 자동화는 AI·백엔드 공고에서 우선한다.
4. 초급 경험을 전문가 수준으로 과장하거나 하지 않은 실무를 만들지 않는다.
5. 예측 정확도, RMSE, MAE, R²는 서로 바꾸어 쓰지 않는다.
6. 연락처·주소·생년월일 등 개인정보는 AI 프롬프트·Git·Notion 요약에 넣지 않는다.

## 추가 확인이 필요한 근거

- 논문 제목·저널·연도·저자 순서·DOI

- 각 프로젝트의 정확한 기간과 GitHub·시연 링크
- 교육 프로젝트별 팀원 수와 기여 범위
- 현재 재직 경력과 최근 업무 성과

확인 전에는 위 내용을 확정 사실이나 숫자로 지원서에 쓰지 않는다.
