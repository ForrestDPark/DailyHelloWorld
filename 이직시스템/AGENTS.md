# 이직시스템 Codex 작업 규칙

이 파일의 규칙은 `이직시스템/` 아래의 모든 작업에 적용한다.

## 작업 시작

1. `README.md`를 다시 읽고 현재 구조·운영 원칙·진행 상태를 파악한다.
2. 노션 `이직시스템` 페이지를 읽고 Git 문서와 상태가 서로 다른지 확인한다.
3. 채용공고는 합격·불합격을 즉시 판정하는 종이가 아니라, 시장이 공개한 학습 커리큘럼으로 다룬다.

## 작업 중

- 사람인·워크넷(고용24) 공식 API를 기본 수집원으로 사용한다.
- 로그인·CAPTCHA·접근 제한을 우회하지 않는다. 사람인 공개 검색결과 페이지 크롤링(`enable_saramin_crawl`)은 로그인/CAPTCHA 우회가 아니므로 예외적으로 허용하되, robots.txt로 막힌 사이트(잡코리아 등)는 절대 크롤링하지 않는다.
- API 키, `config.json`, SQLite DB, CSV, 개인 이력서는 Git에 커밋하지 않는다.
- 사용자와의 대화에서 장기적으로 재사용할 원칙·검색 조건·분류 기준·학습 전략이 나오면 같은 작업에서 `README.md`를 갱신한다.
- 공고는 `지금 지원 가능 / 1~3개월 준비 후 지원 / 장기 목표`로 구분하고, 부족한 기술을 학습·포트폴리오 과제로 연결한다.

## 작업 완료 — 기본 동기화 파이프라인

사용자가 명시적으로 로컬만 수정하라고 한 경우를 제외하고, 이직시스템 작업을 마칠 때 다음을 연속해 수행한다.

1. `./verify_before_sync.sh`로 테스트·문법·비밀값 포함 여부를 검사한다.
2. 해당 작업에서 수정한 `이직시스템/` 파일과 필요한 최상위 `README.md`만 stage한다. 사용자의 다른 dirty worktree 변경은 절대 섞지 않는다.
3. 의미 있는 메시지로 커밋하고 `main`에 푸시한다.
4. 노션 페이지의 `현재 구축 상태`와 관련 설명을 갱신한다. 구현 내용, 사용 방법, 현재 제약, 다음 행동, Git 커밋 해시를 남긴다.
5. Git 푸시나 Notion 수정이 실패하면 완료로 보고하지 말고, 어느 단계가 실패했는지 분명히 알린다.
