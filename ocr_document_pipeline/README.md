# OCR 문서 자동화 파이프라인

이 문서는 **새 세션(다른 기기·다른 클라이언트 포함)에서도 이전 대화 맥락 없이 바로 이어서 작업할 수 있도록** 이 프로젝트의 목적·설계·현재 진행 상태를 기록해둔다. 손자병법 파이프라인(`손자병법/README.md`)·이직시스템(`이직시스템/README.md`)과 같은 목적의 문서.

## 0. 왜 이 프로젝트인가

이직시스템이 수집한 채용공고 중 (주)한중에스에스(AI·전산 업무자동화 담당자) 공고를 분석하면서, **"PDF/스캔 문서 → 텍스트 추출·분류 → 표준양식 자동생성"이 후보자가 아직 실제로 해본 적 없는 유일한 기술 공백**으로 확인됐다(관련 노션 페이지: [채용공고 분석](https://www.notion.so/3b632a1eae8081278fb0e079d8ae26ec)). 견적서·발주서·계약서·수입물류서류처럼 문서가 개인 PC·이메일·종이에 흩어져 검색·표준화가 안 되는 문제는 이 회사만이 아니라 이직시스템이 수집한 여러 제조업·중소기업 공고에서 반복적으로 나타나는 요구사항이다. 이 프로젝트는:

1. 이력서·자기소개서에 바로 쓸 수 있는 **증거 있는 포트폴리오**를 만들고,
2. 이직시스템(`이직시스템/job_collector.py`)과 일본어 자막 추출(`일본어자막추출/`)에서 이미 검증된 **캐시·재시도·중간저장·SQLite·자동 발행 구조**를 그대로 재사용해 빠르게 완성하는 것을 목표로 한다.

**개인정보 원칙(이직시스템과 동일 원칙 적용)**: 실제 회사의 견적서·계약서·발주서 등 진짜 문서는 절대 사용하지 않는다. 개발·테스트에는 직접 만든 가짜 샘플 문서(허구의 회사명·금액·날짜)나 공개적으로 배포되는 샘플 양식만 쓴다. 실제 문서가 든 폴더는 `.gitignore`에 등록하고 Git에 올리지 않는다.

## 1. 무엇을 만드는가

폴더 안의 PDF/스캔 이미지 문서(견적서·발주서·계약서·수입물류서류 등)를 넣으면:

1. **OCR로 텍스트를 추출**하고,
2. **LLM으로 문서 종류를 분류**하고 거래처·금액·날짜·문서번호 같은 **핵심 항목을 뽑아**,
3. 그 항목을 **표준 템플릿(마크다운/JSON)에 채워 넣고**,
4. **SQLite에 저장**해 나중에 거래처·기간·문서종류로 **검색**할 수 있게 하고,
5. 간단한 **웹 화면(Flask)**에서 그 검색을 눈으로 확인할 수 있게 한다.

핵심 문장: **"흩어진 문서를 못 찾고, 반복 문서작업에 시간을 쓰는 문제"를 "넣으면 자동으로 분류·정리·검색되는 파이프라인"으로 바꾼다.**

## 2. 아키텍처

```
문서 폴더(PDF/이미지)
      │
      ▼
[1] ocr_extract.py      — pdf2image/pytesseract로 텍스트 추출, 파일 해시로 캐시(재처리 방지)
      │  (원문 텍스트, 실패 시 재시도 큐에 적재)
      ▼
[2] doc_classifier.py   — LLM API로 문서 종류 분류 + 핵심 항목 추출(JSON), 실패 시 재시도·폴백
      │  (문서종류, 거래처, 금액, 날짜, 문서번호, 신뢰도)
      ▼
[3] template_writer.py  — 문서종류별 표준 템플릿(마크다운/JSON)에 항목을 채워 저장
      │
      ▼
[4] storage.py           — SQLite에 원문 경로·추출 텍스트·분류 결과·템플릿 결과 저장(중복 방지: 파일 해시 기준)
      │
      ▼
[5] search_ui.py (Flask) — 거래처/기간/문서종류로 검색, 표준 템플릿 미리보기
```

각 단계는 독립 모듈로 두고, `pipeline.py`가 순서대로 호출한다. 한 단계가 실패해도 다음 문서로 넘어가고(이직시스템 job_collector.py의 "상세 연결·본문·AI 분석 실패 시 다음 후보로 자동 이동" 패턴과 동일), 실패한 문서는 `retry_queue` 테이블에 남겨 다음 실행 때 다시 시도한다.

## 3. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| OCR | `pytesseract` + `pdf2image`(Poppler) | 로컬에서 무료로 동작, 한글 인식(`kor` 언어팩) 지원 |
| 문서 분류·항목 추출 | Claude/GPT API (이직시스템의 `ai_exec.py` 패턴 재사용) | 이미 검증된 캐시·재시도 구조를 그대로 가져다 쓸 수 있음 |
| 저장 | `sqlite3`(표준 라이브러리) | 이직시스템·shift_alarm과 동일하게 별도 DB 서버 없이 운영 |
| 검색 웹 화면 | Flask | 하루시작 프로젝트에서 이미 Flask/FastAPI 서빙 경험 있음 |
| 테스트 | `unittest` | 이직시스템(`test_job_collector.py`)과 동일 컨벤션 |

## 5. 사용 방법 (구현 후 채울 예정)

```
python3 pipeline.py process ./samples/          # 샘플 폴더 문서 일괄 처리
python3 pipeline.py serve                        # 검색 웹 화면 실행 (기본 127.0.0.1:5050)
python3 -m unittest                               # 테스트 실행
```
